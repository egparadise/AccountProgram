# WEHAGO 홈피스 REA 분석과 독립 재구현 명세

## 1. 결론

바탕화면의 **WEHAGO 홈피스 올인원팩**은 별도 네이티브 회계 실행 파일이 아니라, Chrome이 `--app-id=ocefjkjdjbpoojmcifacgeogcjmoldnc`로 실행하는 설치형 웹 앱(PWA/Chrome web app)이다. 시작점은 `https://www.wehago.com/#/main`이며 비로그인 상태에서는 `#/login`으로 이동한다. 회계·급여의 실제 업무 화면은 메인 포털에서 Smart A 계열 웹 앱으로 연결되는 구조다.

본 프로젝트는 원 제품의 코드·상표·비공개 API·사용자 데이터를 복사하지 않았다. REA로 관찰한 기능 경계와 업무 흐름을 토대로, **로컬 우선 단일 사용자 회계 정산 앱**을 독립 설계·구현했다.

## 3. 관찰된 제품 구조

```text
Windows 바로가기
  -> Chrome Web App 창
    -> WEHAGO 포털 (React + Webpack SPA)
      -> 로그인/회사/사용자/권한/서비스 관리
      -> Smart A 회계·세무 웹 앱
      -> Smart A 인사·급여 웹 앱
      -> 세금계산서·수금·지급·증빙·문서
      -> 협업 서비스(메일, 일정, 전자결재, 드라이브 등)
```

로그인 화면의 관찰된 구성은 아이디와 비밀번호, 비밀번호 표시 토글, 로그인 버튼, 로그인 상태 유지, 아이디 찾기, 비밀번호 찾기, 회원가입, 하단 정책/고객지원 링크다. 인증 토큰이 없는 공개 세션에서는 `E002 Client Wehago Token is not exists` 오류가 콘솔에 나타났고, 인증 뒤 기능은 이 조사 세션에서 실행하지 않았다.

정적 번들에서 확인된 대표 라우트 군은 다음과 같다.

- `accounts/*`: 거래처, 최근/즐겨찾기, 그룹, Smart A 연결, 가져오기·내보내기
- `al/*`: 지급관리, 통장, 매입매출·카드·현금·세금계산서 현황, 증빙, 수금, 세금신고, 문서, 직원정보, 경영진단·예측, 채권관리
- `invoice/*`: 매출·매입 전자세금계산서, 국세청 목록, 수정·대량작성, 전자문서, 결제·영수증, 설정·권한
- `company/*`: 회사정보, 조직·사용자, 서비스 배포, 결제, 보안, 접속·관리자 활동기록
- `taxagent/*`: 세무대리, 기장, 신고진행, 급여, 인사변동, 홈택스·증빙수집, 업무목록
- `expense*`, `attendance*`, `personalpayroll`, `personalcertificate`: 경비, 근태, 개인 급여·증명서
- `mail`, `schedule`, `eapprovals`, `wedrive`, `contacts`, `fax`, `sms`: 협업 부가 서비스

공식 공개 자료도 홈피스가 회계/세무, 인사/급여, 거래처, 전자결재, 일정, 드라이브, 웹오피스 등을 묶는 패키지임을 설명한다.

## 4. 데이터와 업무 규칙 추론

아래는 라우트, 화면 문구, 필드 후보를 종합한 **설계 추론**이며 서버 내부 구현을 관찰한 결과가 아니다.

1. 회사와 회계연도가 최상위 테넌트/기간 경계다.
2. 매출·매입·경비·입출금은 거래 원장과 복식부기 전표를 함께 만든다.
3. 과세 거래는 공급가액, 부가세, 공급대가로 분해된다.
4. 거래처 잔액과 수금/지급 상태가 채권·채무 현황으로 연결된다.
5. 세금계산서는 작성, 발행, 수금의 상태를 가지며 매입·매출 양방향 목록이 있다.
6. 월 정산은 증빙, 전표 균형, 미결 항목, 부가세, 손익을 확인한 뒤 마감한다.
7. 급여는 직원 마스터와 월별 계산/지급 결과를 분리한다.
8. 재무 보고서는 거래 전표를 집계한 파생 결과여야 하며, 원장과 합계가 일치해야 한다.

## 5. 독립 구현 범위

Git 저장소의 `정산ON` 앱은 다음을 구현한다.

| 원 제품에서 확인한 업무 경계 | 독립 구현 |
|---|---|
| 경영 현황·예측 | 연 매출·비용·손익·미수금 KPI, 6개월 추이 |
| 매입매출·통장·증빙 | 매출/매입/경비/입금/출금 등록, 증빙·결제 상태 |
| 회계 전표 | 거래 유형별 자동 차변·대변, 균형 검증 |
| 수금·지급·채권 | 미수·미지급과 거래처 잔액, 완료 상태 |
| 월 정산·세금신고 준비 | 월 손익, 매출/매입세액, 납부예상 부가세, 월 마감/취소 |
| 전자세금계산서 | 매출·매입 계산서 작성, 작성중/발행/수금완료 |
| 직원·급여 | 직원 등록, 기본급/수당/공제, 월 계산·지급 |
| 재무 보고 | 손익계산서, 부가세 요약, 합계잔액시산표, CSV |
| 설치형 웹 앱 | manifest + service worker 기반 PWA |

핵심 회계 규칙은 `src/lib/accounting.ts`에 분리했다. 예를 들어 매출은 외상매출금 차변과 매출·부가세예수금 대변, 매입은 상품매입·부가세대급금 차변과 외상매입금 대변을 만든다. 모든 자동 분개는 차변 합계와 대변 합계를 검사한다.

## 6. 의도적으로 제외한 범위

- WEHAGO 계정, 인증, 결제, 라이선스, 회사 테넌트 API
- 홈택스·은행·카드·4대보험·급여이체 등 제3자 실연동
- 전자세금계산서 법적 발행/전자서명
- 법인세·소득세 조정과 정부 전자신고 서식
- 다중 사용자 권한, 서버 감사로그, 백업·복구, 파일 원본 보관
- 메일·메신저·팩스·화상회의·드라이브 같은 협업 전체 제품군

이 항목들은 비로그인 공개 관찰로 동작을 입증할 수 없거나 외부 기관 자격증명과 법적 요건이 필요하다. 따라서 현재 앱의 계산 결과는 업무 보조용이며 실제 신고 전 세무 전문가 검토가 필요하다.

## 9. 분석 한계

REA의 정적 번들 분석은 캡처된 클라이언트 JavaScript를 전부 파싱했지만 서버 코드, 동적 문자열 조합, 인증 뒤 권한별 화면, 외부 서비스 응답은 포함하지 않는다. 라우트 문자열은 기능 존재의 강한 후보이나 실행 성공이나 사용권한을 증명하지 않는다. 로그인된 사용자의 실제 회계 데이터를 열거나 변경하지 않았으므로, 내부 세부 화면의 픽셀 단위 동일성보다 기능 경계와 회계 흐름 재현을 우선했다.
